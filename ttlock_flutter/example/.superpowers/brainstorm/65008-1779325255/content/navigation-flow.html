App 导航架构设计

先确认整体页面结构，再深入细节

当前问题

  • 扫描页只扫锁，无法选择设备类型
  • 配件页面（门磁、遥控器、键盘、水电表）无路由可达
  • Dashboard 只显示锁，不显示其他设备
  • 锁页面没有配件入口
建议的导航结构
底部 Tab（保持现有 3 个）
📊 Dashboard
/ (首页)
已保存所有设备的概览
锁 / 网关 / 门磁 / 水电表
🔍 扫描
/scan
先选类型 → 再扫描
锁、网关、门磁、遥控器、键盘、水电表
⚙️ 设置
/settings
服务器配置
设备管理（改名/删除）
Detail 页面
🔒 锁详情
/lock/:mac
• 开关锁
• 可配置参数的命令面板
• 🔗 绑定配件入口：门磁、遥控器、键盘
• 配置项（音量、方向、自动锁定等）
📡 网关详情
/gateway/:mac
• 状态查看
• 网络配置
• 已关联锁列表
配件详情页
门磁 / 遥控器 / 键盘 / 水电表
• 设备信息
• 功能操作
• 删除/解绑
扫描流程
选择设备类型
(锁/网关/门磁等)
→
扫描对应类型
(启动对应流)
→
点击设备
初始化/连接
→
跳转详情页

讨论点

以上架构是否符合你的预期？特别是：

  • 底部 3 tab 保持不动？还是需要增减？
  • 配件详情页从锁页面进入（门磁/遥控器/键盘绑定在锁上），水电表和独立门磁从 Dashboard 进？
  • 扫描页先选类型再扫，是否需要在扫描结果中同时显示附近的所有设备类型？

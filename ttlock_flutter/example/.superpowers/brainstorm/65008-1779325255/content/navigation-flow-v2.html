服务器 + 设备管理
扫描页的两种使用场景
场景 A：主扫描（从底部 Tab 进入）
显示设备类型选择器：🔒锁 / 📡网关 / 💧水表 / ⚡电表
选择类型 → 扫描 → 初始化 → 保存并跳转详情
场景 B：配件扫描（从锁详情进入）
传入参数：deviceType=doorSensor|remoteKey|keypad + lockData
不显示选择器 → 直接扫描对应类型 → 初始化时自动绑定到锁
锁详情页结构
🔒 锁详情 /lock/:mac
Section 1：控制命令
• 可配置参数的交互式命令面板

Section 2：绑定配件
• 🔗 门磁 — 查看信息 / 删除
• 🔗 遥控器 — 查看信息 / 添加 / 删除
• 🔗 键盘 — 查看信息 / 添加指纹/卡片 / 删除
每个配件有「添加」按钮 → 导航到扫描页（场景 B）

Section 3：锁配置
• 音量/方向/自动锁定/通行模式等
✅ 关键决策总结：
1. 扫描页接收 ScanConfig 参数（deviceType + lockData）
2. 配件（门磁/遥控/键盘）从锁页面跳转扫描页
3. 水电表/独立门磁从主扫描页进入
4. Dashboard 展示所有设备

需要你确认

1. 扫描页参数化设计是否符合你的预期？

2. 配件扫描初始化时，是扫描到就自动绑定到锁，还是扫描后让用户确认再绑定？

3. 锁详情页的配件区是否只需显示「该锁已绑定的配件列表 + 添加按钮」，还是需要完整的 CRUD 管理？
